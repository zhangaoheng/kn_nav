# 全局重定位模块使用说明

## 1. 模块定位

本模块以现有 `FAST_LIO_LOCALIZATION_HUMANOID` 为唯一运行基准，保留原有：

- FAST-LIO里程计；
- Open3D连续ICP定位；
- `/Odometry_open3d`、`/scan_map`和TF接口；
- 地图切换、导航和Web API接口。

新增模块只负责在初始位置未知或定位丢失时搜索候选位置，不发布速度、不控制底盘，也不直接发布TF。

## 2. 从SC-QN吸收的能力

| SC-QN思路 | 当前ROS2实现 |
|---|---|
| ScanContext场景检索 | 独立实现环形/扇区描述子和旋转搜索 |
| 关键帧候选地图 | 从现有PCD自动建立重叠XYZ地图分块 |
| Quatro粗配准 | 使用描述子航向角和点云中心生成粗位姿，不引入非商业源码 |
| Nano-GICP精配准 | 使用当前工程已有的Open3D多分辨率点到面ICP |
| 匹配结果修正里程计 | 验证成功后可选发布`/initialpose`，仍由原定位节点复核并更新`map→odom` |

没有迁移ROS1、Catkin、ROS1 bag地图、原TF发布方式及调试轨迹。这些内容会破坏当前ROS2接口或带来许可证风险。

## 3. 安全设计

模块有两道默认关闭开关：

```yaml
launch:
  start_global_relocalization: false

nodes:
  global_relocalization_node:
    enabled: false
```

- 第一项控制是否启动进程；
- 第二项控制服务是否允许计算；
- `apply: false`只计算和显示候选，不影响当前定位；
- `apply: true`才会向`/initialpose`发布已通过验证的候选；
- 定位处于`TRACKING`时默认拒绝覆盖现有位姿；
- 即使应用成功，也必须等待`/localization_status`重新进入`TRACKING`；
- 模块中没有`cmd_vel`、底盘SDK或TF广播代码。

## 4. 接口

订阅：

```text
/map_3d              当前离线PCD地图
/scan_base_link      当前base_link坐标系点云
/localization_status 当前定位状态和地图名称
```

发布：

```text
/global_relocalization_node/candidate_pose  候选位姿
/global_relocalization_node/aligned_cloud   配准后的点云
/initialpose                               仅apply=true且验证通过时发布
```

服务：

```text
/global_relocalization_node/trigger
```

## 5. 编译

当前基准项目依赖Open3D 1.4.1 C++ SDK。确保SDK存在后执行：

```bash
cd /home/code/work_space/kn_nav
source /opt/ros/humble/setup.bash
export Open3D_DIR=/home/code/thirdparty/open3d141/lib/cmake/Open3D
colcon build --packages-select pct_scan_navigation open3d_loc \
  --symlink-install \
  --cmake-args -DOpen3D_DIR="$Open3D_DIR"
source install/setup.bash
```

## 6. 离线验证流程

首次验证必须使用rosbag并保持速度桥关闭。

先在运行配置中设置：

```yaml
launch:
  start_global_relocalization: true

nodes:
  global_relocalization_node:
    enabled: true
```

只计算候选，不应用：

```bash
ros2 service call /global_relocalization_node/trigger \
  open3d_loc/srv/GlobalRelocalize \
  "{apply: false, allow_while_tracking: false}"
```

在RViz检查`candidate_pose`和`aligned_cloud`确实与地图重合后，才可以在静止状态测试应用：

```bash
ros2 service call /global_relocalization_node/trigger \
  open3d_loc/srv/GlobalRelocalize \
  "{apply: true, allow_while_tracking: false}"
```

随后检查：

```bash
ros2 topic echo /localization_status
ros2 topic echo /Odometry_open3d --field pose.pose
```

只有状态重新进入`TRACKING`并连续稳定后，才允许恢复导航。

## 7. 参数说明

| 参数 | 作用 |
|---|---|
| `descriptor_radius` | 描述子观察半径 |
| `descriptor_rings/sectors` | 环形和扇区分辨率 |
| `tile_size` | 地图XY候选块尺寸 |
| `tile_height` | 地图Z方向分层高度，防止多楼层混合 |
| `max_candidates` | 进入几何验证的最大候选数量 |
| `voxel_size` | 候选库和ICP降采样尺寸 |
| `min_descriptor_score` | 场景描述子最低相似度 |
| `min_fitness` | ICP最低重叠率 |
| `max_inlier_rmse` | ICP最大内点误差 |
| `max_scan_age_s` | 当前点云最大允许延迟 |

这些阈值必须用每张实际地图的bag统计后确定，不能直接在运动中的实机上试错。

## 8. 当前边界

- 这是新增的实验性恢复模块，不替代Open3D连续定位；
- 尚未经过当前机械狗的离线bag和实机静止验证；
- 对高度重复的走廊仍可能产生相似候选，必须依赖ICP和多帧复核；
- 当前只支持人工触发，不会在`TRACKING_LOST`后自动应用；
- 切图后会根据新的`/map_3d`重建候选库，但仍需等待数据库构建完成。
