# PCT + SCAN 统一配置使用指南

## 配置入口

A2 实机只需要维护：

```text
src/pct_scan_navigation/config/A2/navigation.yaml
```

文件结构如下：

| 分区 | 内容 |
|---|---|
| `launch` | 模式、模块开关、网卡和默认地图 |
| `topics` | 定位、点云、目标点和路径话题 |
| `maps` | PCD、tomogram 和地图定位阈值 |
| `nodes` | FAST-LIO、定位、规划、控制器和底盘参数 |

修改后需要重新启动导航进程。统一启动入口不再读取旧的
`fast_lio.yaml`、`open3d_loc.yaml`、`scan_planner.yaml` 等拆分文件。

修改后可先做离线校验，不会启动任何 ROS 节点：

```bash
python3 src/pct_scan_navigation/scripts/check_navigation_config.py \
  src/pct_scan_navigation/config/A2/navigation.yaml
```

## 常用修改位置

- 启动模式和网卡：`launch.navigation_mode`、`launch.network_interface`
- 默认地图：`launch.initial_map_name`
- 激光和 IMU：`nodes.fastlio_mapping.common`
- 定位阈值：`nodes.global_localization_node`
- 全局地图：`nodes.pct_global_planner.tomo_path`
- 局部障碍：`nodes.scan_planner_node.grid_map.*`
- 局部速度：`nodes.scan_planner_node.manager.*`
- 控制输出：`nodes.closed_loop_controller`
- 底盘限幅：`nodes.go2_cmd_vel_bridge`

首次启动使用的 PCD 和 tomogram，应同时与 `maps` 中默认地图的路径保持一致。
`maps` 分区用于运行中切换地图，节点参数用于进程首次启动。

局部障碍膨胀和机器人尺寸直接影响安全距离。实机调小前必须先确认点云、自身
过滤和机器人真实尺寸，不能为了绕过规划失败直接缩小。

## 编译与启动

```bash
cd /home/ehuy/KN/kn_robot/kn_nav
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-up-to pct_scan_navigation
source install/setup.bash
ros2 launch pct_scan_navigation unitree_A2_pct_scan_navigation.launch.py
```

使用仓库外的配置：

```bash
ros2 launch pct_scan_navigation unitree_A2_pct_scan_navigation.launch.py \
  config_file:=/home/nav_map/navigation.yaml
```

显式命令行参数优先于 YAML。例如仅本次关闭底盘桥：

```bash
ros2 launch pct_scan_navigation unitree_A2_pct_scan_navigation.launch.py \
  start_go2_bridge:=false
```

未显式传入的参数全部使用 YAML 中的值。

## 旧配置迁移

```bash
python3 src/pct_scan_navigation/scripts/migrate_navigation_config.py \
  src/pct_scan_navigation/config/A2
```

该命令会覆盖 A2 的 `navigation.yaml`。迁移后应人工核对地图路径、网卡、
底盘桥开关和安全参数。

## 推荐修改流程

1. 复制当前 `navigation.yaml` 作为本次试验配置。
2. 一次只修改一类参数，并记录修改原因。
3. 先关闭底盘桥，完成配置解析和话题检查。
4. 确认定位、点云及局部栅格正常后，再低速启用底盘。
5. 将验证后的参数合并回 A2 的 `navigation.yaml`。

配置格式错误、缺少必需节点分区或模式不合法时，launch 会在启动节点前报错，
避免不同节点混用新旧配置。
