# 新机械狗部署参数修改指南

本文用于将现有导航系统部署到新的机械狗，说明必须修改或核对的参数，以及推荐的安全部署顺序。

## 1. 配置入口

A2 的主要配置文件为：

```text
src/pct_scan_navigation/config/A2/navigation.yaml
```

启动时也可以指定外部配置文件：

```bash
ros2 launch pct_scan_navigation unitree_A2_pct_scan_navigation.launch.py \
  config_file:=/home/nav_map/navigation.yaml
```

配置修改后可先进行离线检查：

```bash
python3 src/pct_scan_navigation/scripts/check_navigation_config.py \
  src/pct_scan_navigation/config/A2/navigation.yaml
```

该检查只能验证配置结构，不能判断地图、外参和机械狗运动接口是否正确。

## 2. 必须修改或核对的参数

### 2.1 机械狗通信网络

```yaml
launch:
  network_interface: eth0

nodes:
  go2_cmd_vel_bridge:
    dds_domain_id: 0
    sport_state_topic: rt/sportmodestate
```

需要核对：

- `network_interface` 是否为连接机械狗控制网络的实际网卡；
- DDS 域和状态话题是否与机械狗 SDK 配置一致；
- 新机械狗型号是否兼容当前 `go2_cmd_vel_bridge` 和 Unitree SportClient。

查询本机网卡：

```bash
ip -br addr
```

### 2.2 Livox 雷达网络

雷达 IP 不在统一 YAML 中，需要修改 `livox_ros_driver2` 使用的 `MID360_config.json`：

```json
{
  "host_ip": "机械狗工控机的雷达网口IP",
  "lidar_ip": "MID360实际IP"
}
```

同时核对统一配置中的雷达参数：

```yaml
common:
  lid_topic: /livox/lidar
  imu_topic: /livox/imu
  time_sync_en: false
  time_offset_lidar_to_imu: 0.0

preprocess:
  lidar_type: 1
  scan_line: 4
  timestamp_unit: 3
  scan_rate: 10
```

确认雷达与工控机处于同一网段，并检查实际安装的启动文件是
`msg_MID360_launch.py` 还是 `msg_MID360s_launch.py`。

### 2.3 雷达、IMU 和机体外参

更换机械狗或传感器安装位置后，应重新测量或标定：

```yaml
fastlio_mapping:
  mapping:
    extrinsic_est_en: false
    extrinsic_T: [...]
    extrinsic_R: [...]

global_localization_node:
  path_imu_to_base: /home/nav_map/地图名/imu_to_base.txt
  static_tf_imu_link_to_base_link: [...]
  static_tf_motion_link_to_base_link: [...]
```

需要保证以下变换关系正确：

- 雷达相对 IMU 的位姿；
- IMU 相对 `base_link` 的位姿；
- 运动控制坐标系相对 `base_link` 的位姿。

不要在 Livox 驱动、FAST-LIO 和定位节点中重复应用同一组外参。

### 2.4 机械狗尺寸和碰撞范围

根据新机械狗的实际长、宽、高和雷达安装高度修改：

```yaml
scan_planner_node:
  grid_map.double_cylinder_radius: 0.28
  grid_map.double_cylinder_offset: 0.44
  grid_map.body_height: 0.4
  grid_map.obstacles_inflation_z_up: 0.27
  grid_map.obstacles_inflation_z_down: 0.44
```

首次部署时可适当放大碰撞半径和障碍膨胀范围，避免贴近障碍物运行。

### 2.5 地图和定位文件

新场景需要准备相互匹配的：

- PCD 点云地图；
- PCT Tomogram 地图；
- `imu_to_base.txt` 标定文件。

示例：

```yaml
launch:
  initial_map_name: new-map

maps:
  new-map:
    pcd_path: /home/nav_map/new-map/global_map_downsize.pcd
    tomo_path: /home/code/work_space/kn_nav/src/PCT_planner/rsc/tomogram/new-map.pickle
```

PCD 和 Tomogram 必须来自同一场景，并使用相同的坐标系、原点和比例。

当前 `cross-floor-kn` 配置使用自己的 PCD，但 Tomogram 仍指向
`outdoor_global_voxel002_ground.pickle`，部署前需要确认并改为对应地图。

### 2.6 速度和运动限制

需要根据新机械狗的运动能力核对：

```yaml
scan_planner_node:
  manager.max_vel: 0.75
  manager.max_acc: 0.5
  manager.max_jerk: 4.0

closed_loop_controller:
  max_vx: 1.0
  max_vy: 0.4
  max_vyaw: 1.0

go2_cmd_vel_bridge:
  max_vx: 1.2
  max_abs_vy: 0.5
  max_abs_vyaw: 2.0
  max_linear_acceleration: 1.0
  max_yaw_acceleration: 1.2
```

首次测试建议先降到低速，例如：

```yaml
launch:
  start_go2_bridge: false

nodes:
  scan_planner_node:
    manager.max_vel: 0.2
    manager.max_acc: 0.15
  closed_loop_controller:
    max_vx: 0.2
    max_vy: 0.1
    max_vyaw: 0.3
  go2_cmd_vel_bridge:
    max_vx: 0.2
    max_abs_vy: 0.1
    max_abs_vyaw: 0.3
    max_linear_acceleration: 0.2
    max_yaw_acceleration: 0.3
```

在雷达、TF、定位和规划验证完成前，不要使能底盘运动桥接。

## 3. Docker 部署参数

容器启动脚本默认挂载：

```bash
NAV_MAP_DIR=/home/unitree/nav_map
```

新机器应指定实际地图目录：

```bash
NAV_MAP_DIR=/实际地图目录 \
CONTAINER_NAME=kn_nav_humble \
bash docker/amd/run_container.sh
```

部署前检查处理器架构：

```bash
uname -m
```

- `x86_64`：可使用当前 AMD64 方案；
- `aarch64`：需要制作 ARM64 镜像，并检查 Open3D、PCT 和 Unitree SDK 依赖。

## 4. 当前项目需要注意的问题

### 4.1 Docker 源码地址和分支

当前工作仓库是：

```text
https://github.com/zhangaoheng/kn_nav.git
```

但 Dockerfile 中拉取的是：

```text
https://github.com/xuqiang656/kn_nav.git
```

而且 `KN_NAV_REF` 默认是 `main`，不会自动包含当前
`dev/unified-navigation-config` 分支的修改。构建正式镜像前应统一仓库地址，并固定经过测试的分支或提交号。

### 4.2 tmux 启动脚本

`src/tools/open_go2_nav_tmux.sh` 当前仍包含：

- 硬编码的旧容器 ID；
- `unitree_go2w_pct_scan_navigation.launch.py` 启动入口。

A2 部署时应改为实际容器名称和
`unitree_A2_pct_scan_navigation.launch.py`。

### 4.3 Web API 监听地址

Web API 的环境配置默认可能使用 `127.0.0.1`。需要局域网访问时应明确指定：

```bash
python3 ros2_service_api.py --host 0.0.0.0 --port 8000
```

或者：

```bash
export KN_NAV_API_HOST=0.0.0.0
export KN_NAV_API_PORT=8000
```

## 5. 根据现场效果调整的参数

下列参数通常先沿用，再根据定位和规划效果调整：

- ICP 匹配距离、体素大小和适应度阈值；
- GridMap 分辨率、更新范围和射线长度；
- 障碍概率及膨胀参数；
- SCAN 规划范围和重规划距离；
- 控制器位置、航向增益；
- PCT A* 代价阈值和净空权重。

PCT 的部分 A* 参数目前仍位于：

```text
src/PCT_planner/planner/config/param.py
```

这些参数尚未全部纳入统一 YAML。

## 6. 推荐安全部署顺序

1. 确认工控机架构、ROS 2 和 Docker 镜像；
2. 配置机械狗控制网卡、雷达网卡及 IP；
3. 标定雷达、IMU 和 `base_link` 外参；
4. 配置机械狗尺寸和碰撞范围；
5. 准备对应的 PCD、Tomogram 和标定文件；
6. 关闭自动底盘桥接并降低所有速度限制；
7. 依次验证雷达、IMU、TF 和 FAST-LIO；
8. 验证重定位、地图匹配和里程计心跳；
9. 只运行全局及局部规划，确认不发送运动命令；
10. 在架空或安全空旷场地低速使能底盘，逐步调整参数。
